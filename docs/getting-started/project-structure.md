# Project structure

The repository contains two independent parts:

- the **image build**: a [mkosi](https://github.com/systemd/mkosi) configuration that produces a bootable Debian 13 (trixie) disk image, named `CCBDos`;
- the **documentation**: this site, generated by [Zensical](https://zensical.org) from the `docs/` directory.

Day-to-day tasks (build, VM testing) are driven by a [`Justfile`](https://just.systems): run `just` with no argument to list the available recipes.

## Layout

```text
.
├── mkosi.conf                  # Image definition: distribution, packages, boot, output
├── mkosi.postinst.chroot       # Script run inside the image after package installation (services, locales)
├── mkosi.bump                  # Generates the image version (YY.MMDD.HHMMSS)
├── mkosi.extra/                # Files copied as-is into the image root filesystem
│   └── etc/systemd/network/
│       └── 80-ethernet.network #   DHCP on every Ethernet interface
├── env/
│   └── Dockerfile              # Build environment: Debian trixie + mkosi v27
├── Justfile                    # Build, fetch and VM recipes
├── README.md                   # Short project description and link to this site
├── .gitignore                  # Build outputs, local settings and secrets
├── docs/                       # Documentation sources (Markdown)
├── zensical.toml               # Documentation site configuration and navigation
├── requirements-docs.txt       # Python dependencies for the documentation
└── .github/workflows/docs.yml  # CI: builds and publishes the documentation
```

## Image build

### `mkosi.conf`

The main configuration file. It defines:

| Section          | Content                                                                                                                         |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| `[Config]`       | Minimum mkosi version (27).                                                                                                     |
| `[Distribution]` | Debian trixie, x86-64, with the `non-free-firmware` component.                                                                  |
| `[Output]`       | Image ID `CCBDos`, `disk` format, written to `mkosi.output/` as `CCBDos_<version>_x86-64.raw`.                                  |
| `[Build]`        | Cache directory, incremental builds, history, and a dedicated tools tree (Debian trixie) so the build does not depend on the host. |
| `[Content]`      | Bootable image with `systemd-boot` and a unified kernel image (UKI), kernel command line, package list, files removed from the image. |

A few choices in `[Content]` are worth knowing:

- **No recommended packages** (`WithRecommends=no`): only the listed packages and their hard dependencies are installed.
- **Two consoles** (`console=ttyS0 console=tty0`): the serial console is used by `just vm-console`, the screen by `just vm-gui`. The last `console=` receives `/dev/console`, so the first-boot wizard is shown on screen.
- **No machine-specific settings**: hostname, locale, keymap and timezone are deliberately **not** set in the image. `systemd-firstboot` asks for them on first boot, or reads them from systemd credentials (see `just vm-create`). The files set by packages (`/etc/localtime`, `/etc/timezone`, `/etc/locale.conf`) are removed for that reason.
- **No shipped SSH host keys**: they are removed from the image, otherwise every machine would share the same keys. Each machine generates its own at first boot.

### `mkosi.postinst.chroot`

Shell script executed inside the image once packages are installed. It enables the services started at boot (`systemd-networkd`, `systemd-resolved`, `ssh`) and generates the `fr_FR.UTF-8` and `en_US.UTF-8` locales, which `systemd-firstboot` offers in addition to `C.UTF-8`.

### `mkosi.bump`

Script called by mkosi to compute the image version. The version is a timestamp (`YY.MMDD.HHMMSS`) stored in `mkosi.version`.

### `mkosi.extra/`

Tree copied verbatim into the root filesystem of the image. It currently only contains the network configuration (DHCP on all Ethernet interfaces).

### `env/Dockerfile`

Defines the container used for local builds: Debian trixie with mkosi installed by `pipx` from its Git repository (tag `v27` by default, overridable with the `MKOSI_REF` build argument). Its entrypoint is `mkosi`.

### `Justfile`

Entry point for developers. Recipes are grouped as follows:

| Group   | Recipes                                                     | Purpose                                                            |
| ------- | ----------------------------------------------------------- | ------------------------------------------------------------------ |
| `build` | `build`, `sync`, `fetch`, `shell`, `clean`                  | Build the image locally in Docker or on the remote build server.   |
| `vm`    | `vm-create`, `vm-gui`, `vm-console`, `vm-ssh`, `vm-destroy` | Run the image in a libvirt virtual machine.                        |

`just build` builds in Docker by default; `just build srv` sends the working directory to the remote build server (`sync`) and builds there, then `just fetch` downloads the result. Both variants delete previous images before building and write a timestamped log to `logs/`.

Per-user settings are read from environment variables or from a local `.env` file (ignored by git):

| Variable       | Default             | Description                                                |
| -------------- | ------------------- | ---------------------------------------------------------- |
| `CCBD_REMOTE`  | `ccbd`              | SSH alias of the remote build server.                      |
| `CCBD_SSH_KEY` | `~/.ssh/id_ed25519` | SSH key injected into the VM (the `.pub` file must exist). |

See [Building the image](build.md) and [Testing in a VM](vm.md) for usage.

## Generated files

The following paths are created by builds and are ignored by git.

| Path                                   | Created by                         | Content                                           |
| -------------------------------------- | ---------------------------------- | ------------------------------------------------- |
| `mkosi.output/`                        | `just build`, `just fetch`         | Built images (`.raw`), UKI and related artifacts. |
| `mkosi.version`                        | mkosi (`mkosi.bump`), `just fetch` | Version of the last image built or fetched.       |
| `mkosi.cache/`                         | mkosi                              | Package cache, reused across builds.              |
| `mkosi.tools/`, `mkosi.tools.manifest` | mkosi                              | Tools tree used to run the build.                 |
| `.mkosi-private/`                      | mkosi                              | Internal mkosi state.                             |
| `logs/`                                | `just build`                       | Timestamped build logs.                           |
| `site/`, `.cache/`, `.venv/`           | Zensical                           | Documentation build output and virtual env.       |

!!! note "File ownership after a Docker build"
    The container runs as root. After a build, `just build` gives `mkosi.output/`, `mkosi.version` and `.mkosi-private/` back to your user, but `mkosi.cache/` and the tools tree stay owned by root. Use `just clean` to remove them.

!!! danger "Secrets"
    Signing keys and local settings (`mkosi.key`, `mkosi.crt`, `mkosi.local.conf`, `mkosi.credentials/`, `*.pem`, `*.gpg`, `.env`) are ignored by git. Never commit them.
